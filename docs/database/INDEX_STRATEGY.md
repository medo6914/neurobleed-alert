# Index Strategy & Justification

## Index Design Principles

1. Every index must serve a specific query pattern
2. No redundant indexes (covered by composite indexes)
3. Composite indexes follow "equality, then range, then sort" order
4. DESC on timestamp columns for "most recent first" queries
5. Partial indexes for boolean filters with skewed distributions

## Composite Indexes

### sensor_readings

| Index | Columns | Query Pattern | Expected Benefit |
|-------|---------|---------------|------------------|
| `ix_sensor_readings_patient_timestamp` | `patient_id`, `timestamp DESC` | "Get all readings for patient X ordered by time" | Time-series dashboard — most frequent query |
| `ix_sensor_readings_device_timestamp` | `device_id`, `timestamp DESC` | "Get all readings from device X" | Device diagnostics — moderate frequency |
| `ix_sensor_readings_risk_level_timestamp` | `risk_level`, `timestamp DESC` | "Get critical readings" | Triage board — high priority |

**Single-column indexes** (auto-generated by `index=True`):
- `patient_id` — FK query support (partially covered by composite above but used for FK lookups)
- `timestamp` — raw timestamp range queries

## Query Coverage Matrix

|-------|-----------|------|
| `WHERE patient_id = :pid ORDER BY timestamp DESC LIMIT 50` | `ix_sensor_readings_patient_timestamp` | Index Only Scan |

## Monitoring & Maintenance

```sql
-- Check index usage
SELECT schemaname, tablename, indexname, idx_scan, idx_tup_read
FROM pg_stat_user_indexes
ORDER BY idx_scan ASC;

-- Find unused indexes (>6 months)
SELECT * FROM pg_stat_user_indexes
WHERE idx_scan = 0 AND idx_tup_read = 0;

-- Check for redundant indexes
SELECT pg_size_pretty(sum(pg_relation_size(idx::regclass))) as size,
       array_agg(idx) as indexes
FROM (SELECT indexrelid::regclass as idx
      FROM pg_index) t;
```
